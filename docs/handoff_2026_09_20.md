## 1. What the project is

A viewpoint knowledge graph built from survey data (Pew ATP via OpinionQA; ISSP as
a second corpus), embedded in hyperbolic space, with a **divergence scout** that
retrieves pairs of subgroups who disagree about a question. Those pairs are
injected into a generator, which writes several drafts and merges them
(`merge_v2`). Evaluation is **OvertonBench**: an LLM judge predicts each
participant's 1–5 rating of an answer, and a viewpoint cluster counts as covered
when its participants' mean predicted rating reaches 4.

Everything runs on a Slurm cluster (Narval). The generator and judge are
Qwen2.5-72B-Instruct-**AWQ** served with vLLM; the trainable policy for the RL
phase is a 7B LoRA.

## 2. Where it stands in one paragraph

`merge_v2` beats baseline by +0.038–0.050, replicated, and transfers to the ISSP
graph (+0.048 on the 34 of 60 questions it reaches). The *retrieval instrument* is
validated — the learned geometry ranks real subgroup disagreement at rho = 0.755
within axes. But every **structural** component has come back null: curvature
(p=0.88), hierarchy (p=0.34), and per-question routing (nothing beats
always-inject). What remains supported is narrow and honest: retrieving relevant
survey viewpoints, drafting several answers, and merging them losslessly helps;
the geometry, the tree and the routing do not measurably contribute.

## 3. The reasoning chain of the last session

Each step changed what to do next, so the order matters more than the list.

1. **ISSP pooled result looked like a null (+0.024, p=0.11).** Splitting by
   whether the graph resolved the question showed it was *dilution*: +0.048 on 34
   resolved questions, −0.008 on 26 unresolved. The method works where the graph
   reaches; the graph reaches half of a one-module ISSP corpus.
2. **Flat retrieval tied merge_v2** (+0.010, p=0.34), so the tree hierarchy
   contributes at most ~0.01. Curvature was already a well-powered null.
3. **That raised the obvious suspicion**: maybe the geometry cannot rank
   disagreement at all, so max-divergence selection is arbitrary. Tested with
   `validate_divergence.py` against Jensen–Shannon divergence of the raw survey
   distributions — **the opposite**: rho = +0.755 within axes, while the encoder's
   own input features manage only +0.074. The encoder *recovers* the signal.
4. **But the disagreement is tiny** — mean JS = 0.0154 bits. Subgroups answering
   the same ATP question mostly answer alike, so the argmax pair is often barely
   divergent. That is the current best explanation for why every selection rule
   ties. **Retraining the encoder for disagreement is therefore not justified.**
5. **Auditing the scout for why it matches plain semantic retrieval** found the
   mechanism: `lexical_anchors` can never match OpinionQA's `q:`/`ax:` node names
   against a natural question, so it always falls through to MiniLM top-k. Anchor
   choice *is* semantic retrieval; divergence only reorders pairs inside anchors
   similarity already picked. Confirmed on data: merge_v2 draws 4.85 forks from
   2.13 distinct anchors (30 of 180 rows from a single anchor).
6. **The router direction was closed.** `delta_regressor` on the flat run: nothing
   beats trivial always-inject (+0.525 of the oracle gap); graph features −0.040,
   full causal set −0.178, below length alone (+0.118). Its own stop rule fired.
7. **RL became the strongest remaining direction**, and the group-diversity reward
   sidesteps the failure that killed the previous one: it needs no targets at all,
   where the old reward matched survey positions against participant clusters and
   scored 0.152 concordance.

## 5. Next actions, in priority order

1. **Run the coverage funnel** (interactive, no queue). It decides the next push:
   a large "never retrieved" bucket means graph coverage; "retrieved but not
   drafted" means delivery; "no arm covers" means the construct gap. Commands in
   `jobs-running.txt`.
2. **Read the RL gate when it lands.** Its first number (union@8 − within-answer
   at 7B) ends the RL phase outright if it is ≤ 0.03.
3. **Implement `baseline_long`** (~30 lines, not started). merge_v2's answers run
   ~330 words against baseline's ~69 and no length-matched control exists. This is
   the biggest single threat to the headline claim.
4. **Rerun `merge_v2_rand`**, the content control. It was confounded in every
   prior run; `matched_random_fork` now matches the whole block, so it finally
   tests whether fork *content* is load-bearing rather than fork *volume*.
5. **VITAL combined scoring** once both geometry arms finish — curvature at 300
   situations instead of 60.

## 6. Things that will bite a new session

- **Never submit two jobs with the same `OUT=`.** Generation appends and builds
  its skip-list at start, so concurrent writers duplicate cells and the judge then
  unions over twice the rollouts while reporting the requested number. This
  corrupted a VITAL run and a spread run; both needed dedupe and resubmission.
- **Job names come from the script**, so every submission of
  `job_selection_ablation.sh` shows `sel_ablation`. Pass `--job-name=<experiment>`.
- **The graph split seed must match the embeddings' training seed (42).** Node ids
  come from seeded k-means; a mismatch silently retrieves the wrong subgroups.
  Several scripts defaulted to 0 and were fixed.
- **bf16 72B does not fit 4×40GB.** Use the AWQ model; `job_overton_eval.sh`
  defaulted to bf16 and failed with 0.02 GiB of KV cache.
- **Judge validity bounds every coverage number.** Aggregate agreement with humans
  is 0.167 against a ceiling of ~0.76 (human split-half reliability 0.574). With 8
  reference models, ranking-level validation cannot settle anything; the
  informative check is judge-vs-itself within question.
- **The user runs all git commands.** Provide them; do not commit or push.
- **The user's shell is PowerShell locally**, bash on the cluster. Backslash line
  continuations break locally; use single-line commands.

## 7. Open questions worth stating plainly

- Is the parity between divergence retrieval and plain similarity retrieval
  because the available disagreement is small (mean JS 0.0154), because the model
  ignores the distinction (delivery), or because demographic splits are not the
  judge's vote-based clusters (construct gap)? The funnel plus
  `divergence_payoff.py` separate these.
- Does anything reach **minority** viewpoint clusters? Currently both arms recover
  larger-than-typical clusters, and 30–45% of clusters are covered by nothing.
- Is the +0.04 a length effect? Unanswered until `baseline_long` runs.
