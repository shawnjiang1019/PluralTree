WHAT IT ADDS UP TO
------------------
  * merge_v2 > baseline: replicated 6x (+0.038 to +0.069), and transfers to ISSP
    (+0.048 on the 34/60 questions its graph reaches).
  * Every component we can name contributes nothing: curvature (p=0.88),
    hierarchy (p=0.34), divergence ranking, anchor spread, coverage-greedy
    selection. Any substitution for argmax(rel^alpha * W) returns to baseline.
  * The benchmark separates SYSTEMS, not SAMPLES of one system. That bounds
    routing, per-sample rewards and GRPO-style RL.
  * The headroom that is real and large is ACROSS samples (+0.15 to +0.18), not
    within one answer.

RULES (each cost us a run)
--------------------------
  * Two jobs with the same OUT= corrupts the file. Generation appends and builds
    its skip-list at start, so concurrent writers duplicate cells and the judge
    then unions over twice the rollouts. Check squeue --me before resubmitting.
  * Job names come from the script: pass --job-name=<experiment> or every
    submission shows "sel_ablation".
  * Jobs read the code when they START. Pull first; don't push to retrieval/
    while runs are queued.
  * Never compare absolute scores across runs -- baselines differ (0.4899 vs
    0.4975). Only within-run paired deltas.

    "We need answer user's request: ..." instead of a digit.

    trace containing "3 of 5" would have been read as a rating.
  * Interactive runs need HF_HOME + HF_*_OFFLINE + OPINIONQA_DIR exported or
    load_index hangs trying to reach the hub from a compute node.
